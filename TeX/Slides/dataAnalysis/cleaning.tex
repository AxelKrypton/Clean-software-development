\begin{frame}[fragile]{The issue}
Eventually you will come across data from many different
people/groups. Possible problems:
\begin{itemize}
\item Different conventions
\item Different data formats
\item Duplicate entries
\item Damaged/lost/unlabelled files
\item Straight-up wrong numbers
\end{itemize}
\vspace{5mm}
\centering
We are in an era where significant effort is put into\\
ensuring data can be \textbf{readily used and reproduced}.\\[5mm]
\centering
\URL*{https://www.nature.com/articles/sdata201618}{~The FAIR guiding princple}
\end{frame}

\frame{\frametitle{Practical goals for your own work}
What will save you a lot of pain:
\begin{itemize}
\item You know where your data are
\item You can read your old data
\item Sufficient metadata to know what your data mean
\item You can tell if your data got damaged 
\item Your data are homogeneous and/or well organized
\item Your data don't burden supercomputers
\end{itemize}
}


\frame{\frametitle{Toward these goals}
\begin{itemize}
\item Bring data into common format
% Example: Ising code that handles all the different input
% strings of student 
\begin{itemize}
\item Makes it easier to write/debug scripts
\item Helps next person using your work
\end{itemize}
\item Stay consistent with conventions
\begin{itemize}
\item Label files, parameters, output the same way
\item Use the same file type whenever reasonable
\item Follow your group's conventions
% Example: The perlmutter run having .p, and .h5 input, so separate processing
% required 
\end{itemize}
% What filetype should I use?
% - use what your group is using
% - don't compress small files
% - csv, easiest for small files
% - xml, json, yaml hierarchical, maybe appropriate for parameter files
% - p, hdf5 not human readable. former at least is compressed
% params.yaml actually a nice example
\item Try to use already-existing data structures (e.g.
\texttt{yaml} or \texttt{csv})
\begin{itemize}
\item Everyone can leverage already-existing tools
\item Lots of information about format structure 
\end{itemize}
\end{itemize}
}


\frame{\frametitle{Toward these goals}
\begin{itemize}
\item Select a format appropriate for the data
\begin{itemize}
\item There is value in data being human-readable
\item Does a 300KB file really need to be a binary?
\item Do you really need to invent a file format from scratch?
\item Parameter files: \texttt{yaml}, \texttt{xml}, \texttt{json}
\item Large data files: \texttt{npy} or group's preferred binary
\end{itemize}
\item \texttt{tar} together large collections of small files
\item Add \texttt{README.md} for supplemental information
\item \textbf{Perform Cross Checks as you go along!} 
\end{itemize}
\vspace{6mm}

\centering
In general, \textbf{don't overcomplicate things!}
}

\begin{frame}[fragile]{Responsible data management}
\begin{varblock}{example}[\textwidth]{Ex: Archiving data}
Aggregating files helps lessen the burden for supercomputers when backing up
files, storing their location, etc. Anyway you will have a file limit. Good time
to add a \textbf{checksum} to verify data integrity.
\vspace{2mm}

\begin{lstlisting}[style=MyBash]
function _archive { # _archive subfolder
  local subfolder=$1
  if [ -d ${subfolder} ]; then 
    tar -cf ${subfolder}.tar ${subfolder}
    md5sum ${subfolder}.tar > ${subfolder}.md5
  fi
}

function _unarchive { # _unarchive subfolder.tar
  local archive=$1
  if [ -f ${archive}.md5 ]; then md5sum -c ${archive}.md5; fi
  _checkForFail $? "md5sum"
  tar -xf ${archive}
}
\end{lstlisting}
\end{varblock}
\end{frame}
